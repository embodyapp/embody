# Development Web Inspector

> Explore, test, and debug your Embody application schemas and safety rules using the built-in Web Inspector.

---

## 🔍 What is the Dev Inspector?

When developing applications for AI agents, testing tool definitions and verifying safety rules shouldn't require writing one-off scripts.

Embody includes a built-in, zero-dependency **Development Web Inspector** running directly inside the host process at:

```text
http://127.0.0.1:8080/__inspector
```

The inspector provides an interactive graphical interface to visualize schemas, test tool dispatches, and verify how your application behaves when called by different actors.

---

## ✨ Key Inspector Capabilities

### 1. Interactive Tool & Schema Browser
View all compiled MCP tools, Zod dynamic entities, and custom actions:
- Inspect property types, required fields, and default values.
- Review database indexes and storage properties.
- Verify exact JSON Schema representations exposed to AI agents.

### 2. Actor Simulation Panel
Test how your mechanical safety hooks respond to different caller personas:
- **`human` Persona**: Test administrative overrides and human workflows.
- **`agent` Persona**: Test how autonomous agents experience your application, verifying that pre-commit hooks intercept unauthorized changes.
- **`system` Persona**: Verify background job executions.

### 3. Live Action Dispatcher
Execute any action directly in the browser:
- Input JSON forms with real-time validation.
- Live Server-Sent Events (SSE) progress indicators showing real-time percentages and status messages.
- Formatted output visualization for JSON responses and error envelopes.

### 4. Real-Time Audit Log
Inspect the deterministic audit trail generated by the microkernel:
- Caller actor ID and actor type.
- Target action name and timestamp.
- Inputs passed and mutation results.
- Veto reasons and error traces.

---

## 🔒 Production Safety Lock

The Development Inspector is designed exclusively for local development:
- It is enabled automatically when `NODE_ENV=development`.
- In `NODE_ENV=production`, the route is stripped and returns a `404 Not Found` to prevent exposing internal development tools to the public internet.
