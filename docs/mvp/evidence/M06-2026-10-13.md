## Limits, residual risks and cleanup

- Qualified client surface is **Claude Code 2.1.296 direct HTTP**, not other versions, desktop products, stdio bridge, newer `server/discover` protocol or GenUI. Detailed setup/methods/capability/idle/cancellation limitations are in [MCP](../MCP.md).
- 120 seconds is a bounded observed idle interval, not an infinite-idle guarantee or provider zero-instance proof. Actual cloud metrics/cold latency/scale-down remain M17; no M09/production qualification is claimed.
- Separate cancellation notifications cannot reliably target another replica; close/abort the active transport. Execution must cooperate with its signal. In-flight admitted mutations may have ambiguous outcomes; no automatic replay promise.
- Local cancellation audit proves the current `prepared.finish` path, **not durable audit delivery on process exit**. Handler close does not await arbitrary application cleanup. M07 must add a durable audit/in-flight drain and quotas; current fixed-window limiter has no reservation lease to release. These separate M07 gates are not completed by M06.
- Standalone stateful adapter's pre-existing initialize/close race is outside the hosted stateless profile and remains a hardening follow-up. Duplicate JSON text plus structured output adds payload overhead; account for this in M07 limits. No universal serialization/output-schema promise.
- Successful smoke removed private temporary MCP config/credential and local listeners. Owned `embody-m06-verification` PostgreSQL container/network removed; disposable E2E projects self-cleaned; created Node22 detached worktree removed after copying reports. Shared original `embody-local-*` services were inspected and left untouched. Shared test images retained; no global prune or customer mutation.
- No GCP resource provisioning or cloud budget consumed. Model-reported cost is not an infrastructure invoice or spending-cap proof.
